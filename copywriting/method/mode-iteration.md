# Mode: Iteration

Improving or varying an existing batch.

1. **Locate it.** The batch number I give is the lookup key. Never invent or infer one. Search `ads/testing/`, `ads/roster.md`, `ads/winners/`, `ads/losers/`. If it isn't there, ask me for the brief. Never iterate from memory or a description.
2. **Baseline:** the original copy verbatim; what it did (spend, ROAS, hook rate, hold rate, days running); its verdict and why, ranked LIKELY CAUSAL · PLAUSIBLE · INCIDENTAL.
3. **The change:** what changes, what's held constant, and why.
   - Variable test (change ONE thing, name it) or quality improvement (execution moves, angle holds)?
   - Which element: hook · bridge · demo · proof · objection · offer · CTA · length · creator?
   - Hypothesis: "If we change X, Y improves, because Z."
   - A change with no stated reason is a new ad, not an iteration. Run the ideation questions for anything genuinely new.
4. **Guardrails:** don't iterate a loser without naming why it lost. Don't iterate away what worked. Check the change hasn't already been tried.

Present baseline + change + hypothesis for approval before writing.
